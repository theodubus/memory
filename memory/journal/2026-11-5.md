## J-2026-11-15-M — B-0232 : function nom { … } sans parenthèses se lit comme nom ( ) { … }, son corps jugé ; time et case au backlog

> ref : B-0232, B-0234, ADR-0080, ADR-0072, B-0244, B-0245

Dans le lot B-0234, B-0232 fait. Le découpage du hook de l'agent
(`commands._analyser`) lit `function nom`, sans parenthèses, comme
`nom ( )` : le mot qui suit le nom, ou celui de la ligne suivante,
commence le corps d'une fonction ; un groupe `{ …; }` se juge commande par
commande et rend en se fermant l'état d'avant lui, tout autre corps que
bash admet (`if`, `while`, `until`, `for`, `case`, `[[`, un sous-shell)
se juge comme exécuté là où il s'écrit. `function f { git push --force
origin main; }; f` et `function f { rm -rf ..; }; f` sont refusés,
`function f { ls; }; f` passe. Les formes ont été vérifiées par `bash -n
-c` : bash admet tout nom après `function` (`function f/x`, `function if`,
qu'il appelle), un corps après des sauts de ligne et des commentaires, et
`function` n'est réservé qu'en tête de commande (`echo function f {` n'en
définit pas, `"function" f { …; }` est une erreur de syntaxe).

Un défaut voisin corrigé dans le sujet, parce qu'il le bloquait : la
définition lue survivait à un corps sous-shell, et un groupe écrit en tête
de ce sous-shell se lisait comme le corps d'une fonction, qui rend à tort
l'état d'avant lui (`f ( ) ( { cd memory; }; rm -rf ../../projet )`
passait le hook). Lire le corps de `function nom` sur la ligne suivante
ouvrait ce trou à `function f` puis `( … )`, que le hook refusait avant :
la définition ne vaut plus que pour la commande qui la suit, par-delà des
sauts de ligne seulement.

Restent refusées comme illisibles, sans être des définitions mal lues :
après un corps `if`, `while`, `until` ou `for` qui change de dossier, ce
qu'il change devient inconnu, et une écriture dans le projet qui suit est
refusée (ADR-0072, point 6), comme après `nom ( ) if …` ; bash, lui, ne
l'exécute pas là.

Le défaut injecté `fonction-sans-parentheses` (un push forcé et la
suppression du projet dans un tel corps, sur la même ligne ou la suivante)
et son témoin sain (`function f { ls; }; f`, un corps sur les lignes
suivantes, `function f { cd .socle; }; echo ok > policy.toml`) le prouvent.

Deux trous voisins, hors du sujet, vont au backlog, de priorité haute
comme lui (ADR-0080, sa première conséquence) : `time` devant une
commande composée, lu comme une commande simple dont le programme est le
mot réservé (`time { git push --force origin main; }` passe, B-0244), et
les motifs d'un `case`, que le hook ne suit pas (`case a in b) cd /usr;;
esac; rm -rf ../projet` passe, B-0245).

## J-2026-11-15-R — Les bloquants 2 et 3 de la revue du lot B-0234 : l'appel d'une fonction et un mot réservé cité, deux régressions de B-0232, fermés
