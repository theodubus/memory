## J-2026-11-19-T — T-0005 : uv run et poetry run retirés comme des préfixes, leurs options sautées

> ref : T-0005, B-0248, ADR-0082, L-0005

sautées avant `run` comme après, la valeur de celles qui en prennent une

## J-2026-11-19-U — T-0006 : un git push se juge sur ses arguments développés, un argument illisible refusé

> ref : T-0006, B-0254, ADR-0082, ADR-0072, L-0005

`irreversible` (`engine/socle/hooks.py`) juge l'argv d'un `git`
développé avec les variables connues du shell de l'agent
(`_argv_developpe`), un mot qui porte une variable coupé en mots comme
hors des guillemets : `F=--force; git push $F origin travail` est un push
forcé, `B=main; git push origin "$B"` un push sur la branche par défaut,
et le `for` déplié lie sa variable. `push_illisible` refuse un `git push`
dont un argument ne se développe pas (une variable inconnue, une
substitution, `"$@"` d'un corps de fonction), comme ADR-0072 refuse un
chemin inconnu, avec un refus qui dit d'écrire la branche en toutes
lettres ; une option globale illisible (`git -C "$D" push`) ne compte
pas. Le modèle de menace est ADR-0082 : un push forcé ou sur la branche
par défaut, que rien ne rattrape, se refuse aussi quand le hook ne sait
pas le lire.

Choix : les arguments de l'appel d'une fonction dont le corps pousse ne
se lient pas au corps. Le corps se juge là où il s'écrit, où `"$@"` est
inconnu : le push s'y refuse quel que soit l'appel, ce qui couvre `f() {
git push "$@"; }; f --force origin travail`. Lier les arguments à chaque
appel ne ferait passer que des enveloppes qu'un agent n'écrit pas
(`f origin travail`), au prix de suivre les paramètres d'appel en appel ;
c'est l'interpréteur qu'ADR-0082 écarte.

Les tests (`test_un_push_se_juge_par_ses_arguments_developpes`)
échouent sur le parent ; l'auto-test gagne le défaut
`push-par-une-variable`, non attrapé sur le parent, et un témoin sain.
Note de version 2026-11-19-m.
