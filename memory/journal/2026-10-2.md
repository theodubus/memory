## J-2026-10-12-H — B-0044, L2 fait : le hook de l'agent juge ce qu'une commande fait, et la CI est exigée

> type : livraison · ref : B-0044, fichier:docs/recul.md, fichier:tests/test_garde.py

Le deuxième lot de la passe de recul, chaque correctif avec un test qui
échoue sur le code d'avant :

- le hook de l'agent juge chaque commande découpée en commandes simples
  (`moteur/socle/commandes.py`, par `shlex`), et non le texte brut : les 25
  contournements du banc de la passe sont refusés (pushes par `-C`, `-c`,
  `-fu`, `:branche`, `HEAD:refs/heads/main`, publications, `gh api -X
  DELETE`, écritures protégées par le shell, réponses cachées derrière un
  `cd` ou des guillemets), et les 6 citations refusées à tort passent
  (message de commit, heredoc, `grep`) ;
- les réglages de Claude Code (`.claude/settings*.json`) ne s'écrivent plus
  par l'agent, et la trace des hooks d'un commit compte la session qui
  commite : une session aux hooks coupés compte zéro, la CI la refuse ;
- `approve`, `prive installer`, et `answer` ou `relu` sans relais refusent
  d'eux-mêmes sous un agent, derrière le hook ;
- avec `git commit -v`, le diff ne remonte plus dans le message ;
- un renommage donne ses deux chemins : un fichier protégé ou un fichier
  de test déplacés ne passent plus. Le déplacement d'une migration de
  format se juge sous le nom nouveau ; sans cela, la migration de ce dépôt
  elle-même passait pour trois suppressions non validées ;
- le cliquet voit une doc ajoutée à une correspondance code ↔ doc, et un
  plafond de mutation écrit sans sa mesure ;
- R1 : l'état dit si GitHub exige la CI du socle avant de fusionner sur la
  branche par défaut, et l'installation le demande à l'humain. Mesuré sur
  ce dépôt : `main` se dit protégée alors que sa protection classique
  n'exige rien ; c'est son ensemble de règles qui exige la CI « Socle —
  verify, contrôles, auto-test », sans revue des propriétaires du code.

Chaque refus nouveau a son défaut injecté, et un témoin vérifie qu'une
commande qui ne fait que citer une action refusée passe.

## J-2026-10-12-I — B-0044, L3 fait : la frontière de la mémoire privée tient sur des formes réelles

> type : livraison · ref : B-0044, fichier:docs/recul.md, fichier:tests/test_prive.py

Le troisième lot de la passe de recul, les huit constats de la section C,
chacun avec un test qui échoue sur le code d'avant :

- un terme privé se trouve sous ses variantes d'écriture (séparateurs
  quelconques ou aucun, casse et accents ignorés, coupé en fin de ligne),
  borné par une frontière de mot : « acme_corp » et « AcmeCorp » sont des
  fuites, « acmecorporation » non ;
- les noms se lisent comme les contenus : le nom d'un fichier nouveau (hook
  de l'agent, commit, CI), celui d'une branche créée ou poussée (hook de
  l'agent, hook avant push, CI) ;
- le hook lit le texte qu'une commande `git` ou `gh` publie depuis un
  fichier (`--body-file`, `-F`, `gh api -F champ=@fichier`), même hors du
  dépôt ;
- un identifiant privé dans un bloc de code d'un fichier public, et une
  archive publique, ne passent plus ;
- avec une mémoire privée, le cadrage s'archive dans sa zone, et son
  entrée va au journal privé ;
- la liste des termes se reconnaît en clair : déchiffrée, elle ne rend
  plus la mémoire « indisponible », et commitée sans filtre, elle est vue ;
- sans accès à la mémoire privée, ni un terme ni une entrée privée ne
  s'écrivent : l'un écrasait la liste, l'autre devinait son numéro et
  s'accolait en clair au fichier chiffré ;
- « ajout seul » relit la mémoire privée à la base : un fait privé effacé
  passait.
