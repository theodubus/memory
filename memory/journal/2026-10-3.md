## J-2026-10-15-A — Théo valide B-0061 ; corrigé : la mise à jour d'un backlog vide au format 3

> ref : B-0061, J-2026-10-14-W

Théo valide la suite proposée, texte exact : « Je valide b0061 ». La
migration du format 2 au format 3 crée désormais le dossier du backlog
avec son `.gitkeep` quand le backlog n'a aucun sujet, comme l'installation
d'un projet neuf : git ne suit pas un dossier vide, et son ajout à l'index
faisait échouer la mise à jour. Le test de régression
(`test_la_mise_a_jour_d_un_backlog_vide`) échoue sans le correctif, sur la
même erreur que celle constatée : « git add -- memory/backlog : fatal:
pathspec 'memory/backlog' did not match any files ».

## J-2026-10-15-C — Essai sur GitHub : la CI du socle passe dans un projet de chacun des cinq langages ; le balayage de mutation reste à lancer

> type : mesure · ref : D-0025, D-0027, B-0039, F-0019, F-0018, J-2026-10-15-B

La session d'essai a poussé dans `theodubus/tests` le projet jetable du
banc de chacun des cinq langages, une branche par langage, tel qu'il était
commité (le hook avant push a passé). Le workflow « Socle » passe 5 sur 5,
en une minute à une minute et demie chacun, auto-test compris ; sur PHP,
`setup-php` avec pcov puis `composer install` passent (F-0019). Les exécutions :

- javascript : https://github.com/theodubus/tests/actions/runs/38699683887
- go : https://github.com/theodubus/tests/actions/runs/38699691408
- java : https://github.com/theodubus/tests/actions/runs/38699710118
- ruby : https://github.com/theodubus/tests/actions/runs/38699718001
- php : https://github.com/theodubus/tests/actions/runs/38699734337

Le banc de la session d'essai, dans son conteneur, avait échoué au
balayage de PHP faute de pilote de couverture : c'était le conteneur, pas
l'adaptateur.

Deux restes. Le workflow du balayage de mutation (`socle-mutation.yml`),
planifié et lançable à la main, n'est pas connu de GitHub : la liste des
workflows du dépôt ne donne que « Socle », et le lancement manuel rend 404
sur les cinq branches. Les fichiers que pose l'installeur sont du YAML
valide (vérifié pour les cinq adaptateurs) ; supposé : GitHub n'a pas
encore enregistré un workflow sans déclencheur `push` sur ce dépôt neuf.
Et GitHub avertit que `actions/checkout@v4` et `actions/setup-python@v5`
tournent sur un Node déprécié (B-0062). B-0039 reste ouvert pour le
balayage.
