## J-2026-10-22-I — La CI de bd1fc51 rouge : la maintenance automatique de git dans les dépôts jetables de l'auto-test

> ref : B-0076, B-0084, J-2026-10-22-G

Texte exact de Théo : « c'est poussé, vas-y pour B-0084 / Pour Le projet
pilote, ça doit être un vrai projet ? et c'est moi qui doit travailler avec
c'est bien ça ? ».

Son commit de B-0076 (bd1fc51) est sur la branche. Sa CI est rouge sur un
seul test, `test_une_origine_privee_se_prepare_une_fois_sur_plusieurs_fils` :
un `git clone` local de l'origine d'essai, lancé en parallèle, a échoué sur
« failed to copy file to '…/objects/9b/…': No such file or directory ».
Les contrôles et le reste de la suite passent sur ce commit ; le commit ne
touche que l'adaptateur et son approbation.

Cause retenue : les dépôts jetables de l'auto-test ont une configuration
git vide, donc la maintenance automatique de git active ; lancée en
arrière-plan par un commit ou une réception, elle range les objets de
l'origine pendant qu'un clone les copie. Un échec voisin, « hardlink
different from source », était déjà apparu dans une session précédente.
L'auto-test est du produit : la CI d'un projet le rencontrerait aussi.
Correctif : l'atelier coupe `gc.auto`, `maintenance.auto` et
`receive.autogc` par l'environnement de ses commandes ; un test vérifie
qu'il les coupe, et échoue sans le correctif. Que la course vienne de là
n'est pas reproduit ici : c'est la seule écriture dans l'origine pendant
les clones.

## J-2026-10-22-J — B-0084 corrigé : un commit amendé se juge contre le parent de celui qu'il remplace

> ref : B-0084, J-2026-10-22-I

Sur le « vas-y pour B-0084 » de Théo (J-2026-10-22-I). L'avertissement du
hook `commit-msg` sur un correctif sans test comparait l'index à `HEAD` ;
sur un `git commit --amend`, `HEAD` est le commit amendé, qui porte déjà
ses tests. Git ne dit pas à ses hooks qu'il amende, et le script
`prepare-commit-msg` ne transmet pas l'argument qui le dirait (un
`--amend -m` se présenterait d'ailleurs comme un message). L'amendement se
lit donc dans la ligne de commande du `git commit` qui lance le hook, son
processus parent ; le correctif se juge alors contre le parent du commit
amendé.

Éprouvé sur un dépôt jetable, avec un vrai `git commit --amend --no-edit`
et le seul hook `commit-msg` : l'amendement est vu et rien n'est dit ;
détection neutralisée, le faux avertissement revient. Un premier essai
s'arrêtait au hook pre-commit, qui refusait le moteur modifié pour la
trace : il ne prouvait rien, et a été refait.
