## J-2026-10-10-E — L'auto-test trouve cinq contrôles muets à sa première exécution

> type : constat · ref : fichier:tests/test_autotest.py

Première exécution de `socle selftest` : cinq défauts injectés passaient
sans bruit — code changé sans sa doc, entrée de journal réécrite, fait
effacé, valeur attendue changée, mémoire en retard. Cause unique : sur une
branche sans commit propre, la base de travail retombait sur `HEAD~1`, qui
n'existait pas, et tous les contrôles comparés à la base se taisaient aux
étages agent et git. Corrigé dans `outils.base_de_travail` : la base est le
point de divergence, même égal à HEAD.

L'auto-test lui-même avait un trou : il tenait un défaut pour attrapé dès que
le nom du contrôle attendu figurait dans la sortie — or le rapport nomme tous
les contrôles, réussis compris. Il lit désormais la ligne de synthèse des
échecs. Les tests unitaires ont ensuite montré que le gabarit brut d'une
demande passait le lint : ses textes à remplacer contiennent les mots que le
lint cherche. Un trou laissé tel quel est maintenant refusé.

Le dogfooding a ensuite fait refuser trois commandes légitimes par les hooks
de ce dépôt : un heredoc qui citait la commande de réponse humaine sans la
lancer, une référence `commit:` lue à travers un accent grave fermant, et
l'exécution du lanceur prise pour une écriture d'un fichier protégé. Les
trois motifs ont été resserrés, chacun avec son test.

## J-2026-10-10-F — Porte du jalon 2 : l'audit tourne sur chess entier

> type : jalon · ref : fichier:docs/chess/adaptateur.toml

Installation en mode adoption sur un clone jetable de chess (jamais poussé),
avec l'adaptateur proposé `docs/chess/adaptateur.toml` et les plafonds de
mutation repris de chess. L'audit complet tourne en trois secondes environ
et passe : rien ne plante, rien n'échoue. L'installeur a renommé
`chess:CLAUDE.md` en `AGENTS.md`, fixé son budget au niveau actuel (116 000
octets), et passé trois contrôles en avertissement, qui sont autant de
constats :

- 25 chemins cités qui n'existent pas : presque tous des lecteurs de sondes
  (`tools/sonde-…`) qui ne vivent qu'à l'intérieur des rustines de l'attic.
  Une classe de faux positifs pour le contrôle des chemins cités.
- un test de déterminisme, `assert_eq!(best(fen, 4), best(fen, 4))`, pris
  pour une tautologie. Il est légitime : il appelle deux fois pour comparer.
  D'où l'échappatoire `socle: voulu — <raison>`, raison écrite comme pour un
  test désactivé, soumise à validation parce qu'elle assouplit une règle du
  cadrage.
- les modules du moteur hors du cliquet tant que les plafonds de chess ne
  sont pas importés ; une fois importés, le contrôle passe.

## J-2026-10-10-G — Porte du jalon 5, en local : la commande de CI refuse une pull request défectueuse

> type : jalon · demande : D-0003 · ref : url:https://github.com/theodubus/memory/actions/runs/38072067818

Sur un clone jetable de ce dépôt, un commit qui relève le budget de l'actif
de 6 000 à 60 000 octets et cite un fait inexistant : la commande de CI,
`socle ci`, sort en 1 et nomme exactement les deux contrôles,
`cliquet.garde-fous` et `memoire.references`. Sur la branche réelle, la même
commande passe en 29 secondes. Sur GitHub, le premier passage du workflow
(push de la branche) a réussi en une trentaine de secondes, auto-test
complet compris : chaque défaut injecté y est attrapé aussi, sur le runner.
Les contrôles comparés à une base y étaient indisponibles, comme attendu au
premier push d'une branche sans branche par défaut.

Ce qui reste pour la vraie porte : que GitHub empêche la fusion quand le
check échoue, ce qui exige la protection de branche (D-0003).

Deux défauts trouvés en chemin et corrigés : sans branche par défaut, les
étages agent et git n'avaient pas de base (repli sur la branche suivie) ; et
la correspondance code ↔ doc tournait au commit, où le hook ne voit pas le
message, donc pas la dispense qu'il porte (retirée de l'étage git).

## J-2026-10-10-H — Porte du jalon 3 : `socle verify` exécute la CI de chess, et tout passe

> type : jalon · ref : fichier:docs/chess/adaptateur.toml

Sur le clone jetable de chess adopté, `socle verify` avec l'adaptateur proposé
exécute, dans l'ordre : format, clippy, tests de debug, l'auto-test du

pas), le job indicatif sur la dernière toolchain, et le contrôle « le
balayage de mutation tourne-t-il encore », qui interroge l'API GitHub.

Le premier passage avait échoué, et c'était la faute du socle : l'adoption
avait renommé `chess:CLAUDE.md` en `AGENTS.md`, or un test de chess lit
`CLAUDE.md` par son nom — 35 fichiers de chess le nomment. Une correction
silencieuse, exactement ce que le cadrage interdit. L'adoption garde
désormais `CLAUDE.md` quand le projet le lit, y pose la section du socle, et
laisse le renommage à l'humain.

## J-2026-10-10-K — Backlog clos archivé : B-0013

### B-0013 — Répondre à une demande depuis GitHub, sans terminal

> statut : fait · origine : J-2026-10-10-G · ref : ADR-0006, J-2026-10-10-J

Aujourd'hui, une réponse s'écrit par `socle answer` dans un clone : l'agent
ne peut pas le faire à la place de l'humain (son hook le refuse, et une
réponse écrite par lui ne prouverait rien). Pour qui travaille depuis
l'application ou GitHub, un canal par revue de pull request ou commentaire,
dont l'auteur est vérifié par la CI, éviterait le terminal.
